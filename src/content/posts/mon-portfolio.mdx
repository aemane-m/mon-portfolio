<Tldr>

- **Version 1:** a Next.js template (Magic Portfolio), deployed on Cloudflare Pages from GitHub.
- **What it taught me:** Google Search Console and Lighthouse showed real problems — broken image links, a malformed sitemap, heavy images and unused JavaScript.
- **Version 2:** rebuilt with Astro, as a place to publish projects, articles and photos rather than a static CV.

</Tldr>

A portfolio is a small product, and like any product it improves when you look at how it actually behaves. Mine has had two lives.

## Version 1: a template, quickly online

I started by reserving my domain name with [OVH](https://www.ovh.com), then chose an open-source template, **[Magic Portfolio](https://github.com/once-ui-system/magic-portfolio)**, built on **Next.js** and **Once UI**. It gave me a clean structure and content written in **MDX**, which suits articles well.

I deployed it on **[Cloudflare Pages](https://pages.cloudflare.com/)**, connected to GitHub: every push to the main branch rebuilds the site and publishes it within a minute or two. For a first version, that was the right trade-off: online fast, no cost, nothing to maintain by hand.

None of this was visible by looking at the site. It was only visible by **measuring** it.

## Version 2: a place to share things

I also realised I wanted the site to do more than present a CV. I wanted somewhere to **share projects, write articles and publish photos**, and for it to feel like mine. So I rebuilt it with **Astro**:

- **Static first.** Pages are generated at build time and almost no JavaScript is sent to the browser. The few interactive parts (the animated dots on the homepage, the diagrams) are small and load only where they are used.
- **Content as files.** Projects, articles and photos are plain Markdown/MDX files in the repository, organised in collections. Publishing is one command: `npm run new` creates a draft, I edit it, switch the draft flag off and push.
- **Diagrams in text.** The architecture diagrams in my articles are written in Mermaid, so they live in the same file as the text and follow the light and dark themes.
- **Security headers in a file.** A single `_headers` file sets the security headers and cache rules that Lighthouse had flagged.

## What I learnt

- **Measure before you decide.** Search Console and Lighthouse found problems I would never have spotted by eye.
- **A static site cannot call a server route.** Anything that needs a server at request time has to be generated at build time instead.
- **Choose the tool that fits the content.** A portfolio is mostly text and images, so a static-first framework fits better than a full application framework.
- **Write down why.** The point of this article is the reasoning, not the tool.
